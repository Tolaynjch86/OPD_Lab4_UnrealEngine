**Правила команды**

**Ветки**

Формат: тип/описание-латиницей-через-дефис

* feature/ - изменения уровня
* fix/ - исправление багов
* docs/ - документация
* build/ - настройка репозитория и сборки (LFS, хуки, submodule, упаковка)
* test/ - эксперименты и проверки, в main не сливаются

Примеры: feature/level-gameplay, feature/level-visuals, build/git-hooks, test/lfs-migrate

**Коммиты**

Язык: русский.

Заголовок: тип(область): что сделано

* до 72 символов
* глагол в прошедшем времени
* без точки в конце

Типы: feat - новое, fix - исправление, docs - документация, style - внешний вид, build - сборка и настройка репозитория, chore - служебное.

Область - часть проекта, которую затронул коммит, например project, rules, build, level, gameplay.

Описание - по желанию, после пустой строки. Там же пишем Fixes #номер, чтобы закрыть Issue.

Пример: feat(level): добавлен триггер у двери

**Содержание коммитов**

* коммиты атомарные: один коммит - одно изменение
* с One File Per Actor одно изменение уровня может затронуть несколько файлов актёров в Content/\_\_ExternalActors\_\_, их коммитим вместе
* изменение уровня и строка о нём в changelog идут в одном коммите
* перед коммитом в Unreal делаем File → Save All
* бинарные файлы храним только в LFS, новый тип бинарных файлов сначала добавляем в .gitattributes

**Слияние**

* ветки с изменениями уровня сливаем в main только через Pull Request после ревью напарника
* перед git push делаем git pull, чтобы не было лишних merge-коммитов
* перед git pull и переключением веток закрываем редактор Unreal

**Проект**

Прототип от прошлого разработчика, сделан на шаблоне Stack O Bot (Unreal Engine 5.8).
